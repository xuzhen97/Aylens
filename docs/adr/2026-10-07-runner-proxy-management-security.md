# Runner 代理配置的安全管理通道

- Status: Accepted
- Date: 2026-10-07

## Context

Aylens Admin 位于 Gateway，代理与 Provider 执行配置属于 Runner。统一界面管理远程代理需要配置通道，而原架构规定 Gateway 不接触代理凭据。必须明确调整这一边界，并定义保存确认、运行生效及错误恢复语义，避免集中保存秘密或界面成功但运行配置未变。

## Decision

Admin 通过已认证的 Gateway 管理接口操作在线 Runner，Gateway 经现有认证 Runner 连接发送独立配置消息，不将配置操作混入搜索任务。接口沿用现有管理会话、权限及写操作安全防护。

将代理凭据边界明确调整为：Gateway 可以短暂接触并转发提交的凭据，但不得持久化、回显、写入日志或审计。Runner 是代理配置与凭据的持久所有者。此调整不允许 Gateway 获取 Chrome Cookie、登录态或承担目标网站访问。

凭据仅写入，读取返回白名单脱敏字段。编辑明确区分保留、替换和清除，不将脱敏占位符作为真实凭据。日志和错误消息不得包含原始配置消息、凭据请求体或带凭据的代理 URL。

远程配置写入要求 HTTPS 与 WSS，本机 loopback 开发连接可例外。TLS 终止部署根据明确可信的反向代理配置判断安全连接，不信任任意转发头。非本机明文连接可保留原有运行用途，但拒绝代理配置写入。

仅允许在线修改，不在 Gateway 暂存凭据或建立离线配置队列。写入携带配置版本，拒绝过期版本以防并发覆盖。Runner 完成校验、本地数据库事务和运行配置切换后才回报成功；切换期间不向新任务暴露半更新状态。失败不得静默留下持久状态与活动状态不一致，无法安全恢复时停止接收新任务并明确报告故障。

正在执行的任务固定使用开始时取得的配置版本，新任务使用新版本，HTTP 配置变更无需重启 Runner。被 Provider 或 Profile 引用的代理不得直接删除。

连接中断或回执超时意味着结果待确认，不意味着写入确定失败。协议关联操作与回执；界面重新读取 Runner 配置和版本核对，不盲目重复写入。

Chrome 进程启动时确定浏览器代理。保存配置不自动关闭或重启 Chrome；相关 Profile 明确提示需重启对应 Chrome 才能生效，不声称现存浏览器出口已经更新。

## Consequences

- 可以在统一 Admin 管理代理，同时避免 Gateway 数据库集中持有 Runner 秘密。
- Gateway 成为凭据的短暂传输处理方，其内存、日志、异常和消息处理必须纳入安全审查；这不等于端到端加密，也不保证 Gateway 永远无法看到秘密。
- Runner 数据库仍包含代理秘密，第一期无应用层静态加密，部署与备份必须保护本机敏感文件。
- 在线确认和版本控制减少同步歧义，但离线 Runner 无法预配置，断线时可能需要用户刷新核对。
- 配置切换需要任务级版本隔离，不能简单逐项修改共享 TransportRegistry。
- 浏览器配置保存与进程实际生效分离，界面必须明确提示，不能自动破坏用户登录工作区。
- 现有网络出口与 SSRF 约束仍然有效；管理代理不授权绕过 url-fetch 的公网策略或受控出口要求。

## Alternatives considered

- **Runner 本地配置入口，Gateway 只读状态**：可以保持凭据完全不经过 Gateway，但不能满足统一 Admin 编辑的选择。
- **Gateway 集中持久化代理并下发**：扩大秘密集中存储面，引入离线队列及同步问题，不采用。
- **保存后重启 Runner 或 Chrome**：实现直接，但会中断任务或登录窗口，不符合在线新任务生效及浏览器另行重启的规则。
- **直接修改共享 Registry**：容易让同一任务读取混合配置，也缺乏原子确认，不采用。
- **将超时视为失败并自动重试**：无法区分已提交但回执丢失的情况，可能造成重复写入，不采用。
