# url-fetch 的网络与持久化会话安全边界

- Status: Accepted
- Date: 2026-10-07

## Context

url-fetch 接受调用者提供的 URL，并在 Runner 上访问目标。Runner 可能连接内网、云元数据服务或代理，任意 URL 获取因而具有 SSRF 风险。浏览器兜底复用持久化 Profile，可以读取已有登录态下的内容，同时会执行页面脚本并产生子资源请求。仅校验初始 URL 或仅允许 HTTP/HTTPS 不足以约束这些访问。

## Decision

默认仅允许公网 HTTP(S) 目标，拒绝 URL 内嵌凭据及私网、回环、链路本地、保留地址、云元数据等非公网目标，覆盖 IPv4、IPv6 和映射形式。每一跳重定向执行相同校验。直连必须将实际连接绑定到通过验证的解析地址，同时保持原域名 Host、SNI 与 TLS 证书验证，避免校验后重新解析造成 DNS rebinding 空隙。

HTTP 阶段匿名获取，不读取或导出 Chrome Cookie，不转发调用者任意认证头。HTTP 已获得有效正文时直接结束，不为比较登录后内容启动浏览器。

浏览器仅作为条件最终兜底，复用持久化 Profile：Provider 显式 browser.profile 优先，否则使用 Runner 的 defaultBrowserProfile；默认配置指向 browser-main。沿用 Profile 并发锁，每次请求使用独立页面，结束后关闭页面而不关闭共享浏览器。不自动登录、不解验证码、不自动点击或递归浏览。

浏览器和代理路径不得绕过 HTTP 的安全拒绝。代理远端 DNS 解析、浏览器子资源、iframe、fetch 与 WebSocket 必须纳入出口约束。强网络安全保证依赖可信受控出口代理或网络隔离；不具备该条件时，限制这些路径的目标范围或拒绝无法安全完成的访问，不将本地 DNS 检查或页面请求拦截宣称为完整 SSRF 防护。

获取结果和日志不得包含 Cookie、认证头等凭据；URL 与错误日志应避免泄露敏感查询参数。登录态获取内容不得进入公共缓存；首版不实现持久缓存。

## Consequences

- 已有登录态可提高部分网页的可读性，但 Profile 不是安全隔离边界。任意页面脚本可能携带站点会话发起请求；独立页面与并发锁不能消除会话副作用。部署者必须理解并接受这一边界。
- 使用 browser-main 不放宽公网访问策略，也不允许访问内网管理接口。无安全出口条件的浏览器或代理兜底可能被拒绝，不能以成功率为理由静默降级安全要求。
- 网络策略需要在实际连接与出口生效，不能只检查 URL 字符串。测试须覆盖私网重定向、IPv6/映射地址、DNS 连接绑定，以及代理和浏览器路径的策略执行。
- Browser Profile 的账号与代理配置继续由 Runner 管理，Gateway 不持有浏览器凭据。Provider 无浏览器时仍可完成安全的 HTTP 获取。
- 登录页或挑战页在兜底后仍未解除时必须明确失败，不得作为成功正文返回，也不承诺绕过访问限制。
- 后续如引入缓存、私网访问或 Cookie 共享，必须重新审查授权、隔离及数据泄露风险，不能视为本决策已授权的扩展。
- 具体出口机制若改变已批准设计范围，需要重新确认；本记录不授权新增出口服务或降低安全约束。

## Alternatives considered

- **默认隔离、无登录态的浏览器**：减少已有账号暴露与会话副作用，但用户明确选择默认复用持久化登录 Profile；仍保留 Provider 显式指定其他 Profile 的能力。
- **将 Chrome Cookie 导出到 HTTP 引擎**：可能减少浏览器使用，但扩大凭据处理面、涉及 Cookie 作用域与生命周期，首版不采用。
- **只校验初始 URL 或域名字符串**：实现简单，但无法处理私网解析、重定向、DNS rebinding 和浏览器子资源，不满足网络边界要求。
- **仅在浏览器中拦截请求**：可作为补充措施，但无法独立保证代理远端解析、全部子资源通道及实际连接目标安全，不能替代出口控制。
- **默认允许内网访问**：便于读取内部系统，但让通用获取能力暴露 Runner 的内部网络，超出首版范围。
